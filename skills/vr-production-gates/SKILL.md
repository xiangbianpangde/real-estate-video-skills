# 房产介绍视频制作流程

## 默认与授权边界

**有限探索 → 实际提交真实源图文脚本 → 一次拍前审核 → AI自主完成获批制作 → 用户按脚本审成片。** 发布另行授权。用户参与正常制作的两个节点是拍前和拍后，不再默认逐镜、逐层请求许可。

默认一镜到底，先读 [连续镜头规范](references/continuous-take.md)：MOV-006同点回转、MOV-007跨房间行进、`approved_cut_exception`获批非连续例外。连续镜头中的段落ID不是切点，不以单点/硬拼替代全屋覆盖。

- 拍前一次批准可同时覆盖拍法、一次正式采集、首尾包装、字幕、素材库BGM、已列配音/音效、导出和QC。后期已在范围内就自主完成，不等母版人审或再申请各层许可。
- 事实、权利、范围不清时集中列待确认项，未决部分BLOCKED；**不因此自动切换逐镜审批**。仅用户明确要求“每镜单独确认”时采用该节奏，仍需实际展示图文脚本和绑定许可；旧局部许可不扩为整片许可。
- **先锁修复对象**：修Skill/验证规则只修改canonical和必要配套、运行strict/现有CLI/真实loader及新会话行为验证，核最终差异/原件SHA；合成fixture只证门禁，不证画质已修。已授权修复自主做到验收，不再索“开始”许可。不自动打开房源、导航采样或录制；视频后期、换成像方式重新生成、修模型是不同任务。“继续”只延续已对齐对象/范围，不解除“不重拍”；缺真实新模型不阻塞Skill修复。
- 只冻结整体设计、只接受旧母版，均不授权生产。旧批准不追认为当前完整制作批准。发布、未列付费、新事实/CTA和第二次拍摄不自动解锁。
- **画面接受由用户定义**：先读[用户视觉基准](references/visual-acceptance.md)，按其认可参考的实际整体效果评审、披露现象；不自设零重影/零变形门槛。基准内可记`PASS_WITH_LIMITATIONS`，不要求另批同类缺陷或强制换拍法；建议更高画质不作阻断。参考可作为用户评价标准，不能替当前路线证据或最终人审。
- 现有项目规则冲突须先指出并按实际指令优先级处理；用户当前接受范围优先于旧AI更严门槛，不改冻结历史。

## 1 · 读入与有限探索

1. 读唯一实时状态、风险、事实档案、当前合同和源资产；绑定当前房源/Work、模型/贴图或源面SHA。新房源用自己的输入，不继承别房源的路径、点位、许可或原点例外。
2. 先定义覆盖/顺序、目标时长及容差、核心对象/辅助锚点、运镜和成片样式，再规划**完整候选路线**；允许先设计后核查，候选不是已验证路线。
3. 默认预算：一次关键点/连接预检；每个已登记问题最多两组有假设的局部单变量对照；一次整条路线预检。保存缺陷台账、变量、检查范围与停止理由；复用有效证据，不为小角度重跑全屋、不重新拆名延长预算。
4. 两组无改善、已足以定位源限制或达到预算即停止该问题；提交限制/阻塞清单及选项，不无限换角度。局部变更只复查受影响段及相邻连接。需要扩预算时说明要解决的唯一疑点并获用户明确同意，不能自行续跑。
5. `model_render/model_only`按 [模型摄影合同](references/model-capture-contract.md) 检查轨迹、明显穿模、构图、遮挡、缺面和纹理；不以前现场米制眼高/净空阻塞，不宣称现实安全。`physical_verified`另需现实尺度、1.5–1.6m眼高和沿程0.5m净空证据。
6. 登记当前方法/源/配置，按[动态预检](references/continuous-take.md#成像方法与动态预检)审完整相关区间；旧方法PASS不替当前证据。重影/拉伸/碎片是观察项，按[用户视觉基准](references/visual-acceptance.md)比较，符合范围保留限制，不自动FAIL；差异不明集中待审，确认超范围才停。不以端点/loaded/编码代替画面，复用已有有效媒体，不为标准更正重录。
7. 预检报告与连续媒体/遥测/目视记录/状态恢复证据纳入本版输入SHA；拍前门禁核方法/源/路线/配置绑定。SDK运动要核实际相机、完整状态同步和恢复，不能只取辅助相机矩阵；复用渲染器回归FOV轴/竖屏两轴尺度。报告结构通过不等于自动视觉认证。

## 2 · 图文脚本与一次拍前审核（所有拍摄均适用）

先读 [图文脚本与提交协议](references/illustrated-script.md)，复制 [脚本模板](references/illustrated-script-template.md) 和 [批准记录模板](references/freeze-record-template.json) 到私有项目新版本；不得覆盖历史脚本。

1. **实际交付**：整体方案PNG + 按S01/S02编号的章节图卡。每卡嵌当前房源真实源参考PNG，写时间、动作、重点、字幕/黄标、音乐和风险；附完整口播（或明确无口播）、事实/权利/来源、路线证据、输入SHA和验收标准。纯文字技术表、抽象示意图或只报文件路径不算提交。
2. **成片方案**：首镜是否展示户型图、连续室内背景、尾镜室内收束/CTA、白黄字幕、BGM来源/授权池与零新增付费等均列清。当前明确文字要求优先于示例旧横扫、硬切或户型图收尾；示例只约束所选格式。
3. **字幕**：独立声明`verbatim_voiceover`完整口播或`editorial_keywords`卖点压缩，以及`burned_in`/`selectable_track`/`both`。视觉样式不决定覆盖范围；无法从请求确定时集中澄清。标题不代替口播。
4. **审稿**：逐句核证事实与可见性；读 [文案禁用清单](references/文案/文案中不能出现的内容.md)，公摊及同义解释只供内部核验，不进入旁白、字幕、标题、CTA或素材文字。冲突回审，不擅自删句/改音轨。
5. **版本绑定**：正文、PNG、生产输入与范围同版。执行拍前检查`--phase review`取得正文SHA和`BUNDLE_SHA256`；实际呈现完整图文内容及这两个摘要，再索取批准。保存真实会话提交事件和随后用户回复，禁止伪造事件或把路径-only“批准”追认为内容审核。
6. **一次批准**：`SCRIPT_APPROVED_ONCE`覆盖一次采集与列明后期；入口`--phase capture --claim`核当前动态证据/真实展示批准，退出0才占新take目录，失败仍消费。视觉可为`PASS`或绑定用户依据及比较/披露的`PASS_WITH_LIMITATIONS`；缺证据、未决/超范围FAIL、控制失败或SHA漂移拒绝。用户明确改接受标准时另出报告，不伪写无缺陷，也不额外重复索权。
7. 已展示/获批内容改动必须新版本、新提交/批准，不静默重写或沿用DRAFT文件名。仅批准设计时记`ACCEPTED_FROZEN`，不启动拍摄；详见 [整体方案](references/overall-plan.md)。

## 3 · 批准范围内自主制作

1. 重新核输入、脚本/范围摘要和拍摄claim。**只一次正式采集**，记录源、画布/视口/SAR/FOV、轨迹时间与位姿、原始流SHA，原件不可覆盖。采集失败保留，不自动重拍，不把多个take拼成连续。
2. 自主完成首尾包装、已批准配音/素材库BGM、字幕、混音和编码。静默连续母版是中间文件；方案要求音乐/字幕却只交静默MP4，不算完整成片。不必等母版人审，也不逐层索权。
3. BGM/SFX记来源、授权、SHA、格式/采样率/码率与电平；TTS记provider/model/voice/语言/SHA，候选不等于接受。音乐不能盖旁白，循环/淡出入记录，字幕按最终音轨重排、不越界。
4. 在同一母版和已批准范围内的字体、位置、混音、编码纠错可输出**独立后期版本**，不算第二次拍摄、不另要拍摄许可；保留失败版本。改变事实、CTA、来源/权利、覆盖、时长、成本或拍法先回审。用户已声明不重拍时，回审也不能自动发起新take。
5. 同次制作后期`--phase post`核原批准与claim，不新占拍摄许可。仅后期的新批准设`execution_mode=post_only`、去除`capture`动作、绑定原母版SHA，用该分支核新版审阅；拒绝采集，不给历史take补claim。检查器不是权限沙箱，不认证房况/身份、拦截任意绕过或替代视觉QC。

## 4 · 自主QC、拍后审核与交付

- 技术：编码、720×1280等约定尺寸/SAR、帧率/CFR/帧数/时长、全解码、音轨；按本片合同，不机械套案例参数。
- 画面：按用户已声明基准核段落覆盖/空间关系/整体观看效果、运动/主体/纹理与投影。报告实际差异，参考内的过渡伪影不自动拒收；超出或不明才回审。保留限制，不为满足AI更严要求补洞、遮盖、删覆盖或强制换硬切；基准改变另记评审，不抹除历史。
- 字幕/首尾：读 [字幕规范](references/subtitle-style.md) 和 [首尾协议](references/opening-ending-layout.md)，首/中/尾分别验结构、实帧字形/包围盒、户型比例/主体、口播覆盖与同步；正文白字粗黑描边、1–2处黄标、单行居中无底框，获准版式例外另记。
- 浏览器：确切最终文件从起点播放至ended；自动播放受阻先真实点击。保存SHA、媒体/console/page错误、播放日志；动态实播与音轨实听不能由静帧、机器全绿或模型自述替代。
- 拍后交完整视频、脚本段落/实际时码对照、输出SHA、QC和限制，用户按S-ID接受/退回。`technical_passed`、`human_accepted`、发布授权分开；AI不写自身“符合脚本”为用户接受。
- 同步唯一实时状态和append-only LOG；只展示状态证据，不倒写历史批准。成果路径、许可范围、已验证/未验证、人审与未授权事项必须明确。
