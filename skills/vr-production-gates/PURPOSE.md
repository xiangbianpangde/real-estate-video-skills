# PURPOSE

本文件说明这个 Skill 为什么存在、解决什么问题，以及它对应哪些 wiki 模式。

字幕迭代接手与后续优化顺序见 [HANDOFF.md](HANDOFF.md)；它是交接快照，不替代运行规则或媒体项目实时状态。

## 存在理由

房产介绍视频的失败很少发生在单个技术动作上，而发生在**跨阶段的隐式推进**上：单镜合格就以为成片合格、母版接受就以为后期可以发、机器检查通过就以为用户认可。每一处隐式推进都会绕开真实性与验收门禁。

这个 Skill 把这些边界写成可执行步骤，让 AI 在真实房源视频生产中不会因为"看起来顺"而跳过门禁。

## 解决的问题

1. 单镜合格不等于成片合格 → 默认一镜到底，先证空间连续性，再脚本先审/一体化执行，用户按脚本验收。
2. 技术检查通过不等于内容可读 → 字幕字形、抽帧目视及口播覆盖模式（完整转写/卖点压缩）进入硬门禁；视觉参考不能替代文字覆盖范围约定。
3. 旧接受被误当许可，或完整批准后仍逐层索权 → 旧范围不扩大，但一次明确批准的完整制作自主完成；技术/用户接受/发布分开。
4. 配音、音乐与画面时间轴错配 → 按叙事段和最终音轨重排，章节不是切点，字幕不越界。
5. 渲染器能力缺口导致交付物"看起来成功" → 先测能力再写实现。
6. 无限探索/路径-only审核 → 缺陷台账和停止线、真实源图文实际提交、版本绑定批准与一次采集claim。
7. 旧全景/静态端点PASS误放行新Model/跨点成像 → 当前源/方法/路线/配置动态证据绑定；控制/视觉/实播分项检查，已知FAIL停止而非精确归因后才能决定。
8. 把修Skill误当重新拍视频 → 先锁修复对象，只改canonical/门禁并验证，不因真实视频输入不足暂停规则任务。

## 不负责的事

- 不查房源、房价、学区与政策。
- 不写推广文案或运营策略。
- 不替代通用视频剪辑与转码工具，只在房产视频的制作门禁层面约束行为；不凭 Skill 文档本身宣称跨房间行进已验证。
