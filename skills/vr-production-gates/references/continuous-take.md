# 一镜到底：默认策略与证据分流

## 先定范围，不先定角度

开始任务时记录房源命名空间、覆盖空间与观看顺序、目标时长、核心对象、辅助锚点、观众应读懂的关系。用户要求跨房间或全屋时，不得擅自降级为单点公共区，也不以旁白提及代替实际画面覆盖。默认一镜到底；只有用户明确许可切镜才使用 `approved_cut_exception`，标明非一镜到底；“考虑剪辑/加速”不等于允许切镜。最新一镜到底要求撤销旧切镜方向，不沿用旧草案许可。

| `continuity_class` | 方法 | 必须成立的条件 |
|---|---|---|
| `same_point_rotation` | MOV-006 | 同一原生原点、真实同点六面源、全程无位移；全方向/候选弧线抽样与源面覆盖核验 |
| `cross_room_travel` | MOV-007，可结合 MOV-006 | 同一连续轨迹及所属验收分支的路径/画面证据；模型内检查几何/遮挡/纹理，现实核证另查尺度/眼高/净空；不同点位不能硬拼成行走 |
| `approved_cut_exception` | 用户批准的非连续方案 | 明确批准顺序/切点/输入范围与SHA；完整脚本整包获批后不强制逐项人审；不称为一镜到底 |

连续镜头可分叙事段，章节不是切点；浮层不能遮盖轨迹断点。官方Panorama导航过渡的表现按[用户视觉基准](visual-acceptance.md)评审，不一概等同伪造连续。额外AI补洞/伪拼行走、变焦或加速掩盖未接受差异仍不授权。

## 拍摄介质与验收范围先分流

脚本必须声明 `capture_medium` 和 `validation_scope`，不能把现实安全要求套到模型摄影上。字段与通过定义见 [模型摄影合同](model-capture-contract.md)。

- `capture_medium=model_render`、`validation_scope=model_only`：使用当前房源真实采集的3D模型与贴图连续渲染；取证来自模型几何、相机轨迹和实际沿程画面。现场测量、独立公制尺度及现实眼高/净空不作为前置；模型单位下的眼高/避障参数按画面测试决定，不称现实米制或安全认证。必须检查明显穿墙/穿家具、跳变、缺面、遮挡与纹理畸变。稀疏射线或端点坐标到达不等于全段通过。
- `validation_scope=physical_verified`：若要求现实实测行进、安全或公制主张，再执行下节物理门禁。
- 当前房源已指定某一模型作为后续唯一拍摄源时，冻结模型/贴图SHA和Work身份；六面图仅作为视觉参考或回归依据，不用全景跳点/拼接替代模型连续摄影。新房源必须使用自己的模型，不复用其他房源几何。

模型摄影不是AI补画面；允许忠实渲染已采集模型，不允许补造房间、移除家具或修补成不存在的房况。模型中的连续相机轨迹可称模型内一镜到底，不宣称真人现场行走。

## 成像方法与动态预检

先确定拍摄表达，再选择与当前源/授权匹配的成像方法。文件存在、源SHA相同、模型loaded/refined或SDK导航可调用只证明身份/加载/接口，不证明画质。`capture_medium`与`render_method`须配对：

| 介质 / 方法 | 可用表达与限制 |
|---|---|
| `panorama_reprojection` / `panorama_same_point` | 同一原采集点六面照片回转；照片不提供正确的新位置视差，不能用缩放或跨点拼图称行进 |
| `model_render` / `model_mesh` | 已采集模型/贴图生成新视图；原采集点也可能有伪影，先检查目标结构，不假定移动才会坏 |
| `panorama_navigation` / `panorama_sdk_navigation` | 官方真实全景跨点导航可能有过渡重影/拉伸；按用户认可参考及当前整段效果评审，可带限制通过；端点/名称不替动态证据 |
| `physical_capture` / `physical_camera` | 当前真实连续实拍；来源/权利与现实核证仍按其合同 |

旧同点全景通过不能证明Model、全景跨点或新房源通过。方法/源身份/配置/路线变化，旧证据标不适用；这是证据边界，不自动授予切换方法或新采集。已指定Model为唯一摄影源时，改用Panorama需要对齐范围；重新生成不是原MP4的`post_only`，不能改称“预览”绕过采集/探索预算。

### 最小判断顺序

1. 复用已有身份、目标静帧及失败证据；没有足够证据时，在**原预算内**核关键目标和风险连接，不增加一层全屋试跑。
2. 目标静态的碎片/错接/变形先记事实，按用户标准核主体/空间表达；不把AI无伪影理想当合同。明显不同于参考且是否接受未知则集中待审，确认超范围才FAIL；静态可读仍不证移动可用。
3. 在原预算内取得完整连续画面，实际读回运动与主体展示区间，并核相机/配置；按[用户视觉基准](visual-acceptance.md)比较整体效果。参考内同类过渡重影可`PASS_WITH_LIMITATIONS`，不凭某一帧自动拒绝或要求换硬切；端点/回调/全解码不替动态审看。确认超范围才停止，避免为无瑕疵追加探索。
4. 技术/控制、现象、是否符合用户标准、完整实播、最终用户接受分开记录；机制未知如实写，不逆向到精确原因才交付。标准改变用已保存媒体另评审，不抹除旧FAIL、不重录。
5. 原始流、实际媒体PTS与墙钟均留存；`captureStream(30)`不是CFR30保证。墙钟/时间戳漂移、编码/帧数/停留不符就披露，不重录/插帧/变速让断言变绿。
6. 超出用户范围的FAIL或预算耗尽停止随机续试/全屋重复运行。用户已给可接受参考时，先复用原媒体按其标准比较，不以旧AI更严FAIL强制换源/换形式，也不因标准修订自动重开预算。新数据/方法仍需自己的证据；修Skill不因视频输入缺口阻塞。

### SDK状态控制与恢复

- 先保存独立会话的URL、viewport/DPR、主相机pose/实际位置、state/mode/pano、投影与有效view offset、`syncState`自有属性及被改helper。旧会话已blank/换页面时不能复用旧恢复基线。
- `setState`/模式切换后等待实际加载、controller/tile ready，并回读**实际主相机**与目标误差；同模式调用可能不生效。内置辅助`perspectiveCamera`的identity matrix不能冒充主相机矩阵，FOV须标水平/垂直轴。
- 优先官方状态/API。在外部驱动导航时，旧state同步可能在回调后拉回镜头；若需要临时挂起同步，必须限定执行窗口、保存属性描述符，并在`finally`对齐实际state后恢复原描述符，原无自有属性则`delete`恢复继承方法，不能赋`undefined`留假恢复。不得用静帧强置pose制造移动已达成的证据。
- 保存实际运动/完成/取消、帧位姿与完整媒体。轨迹/构图任一控制守卫失败，该尝试为INVALID，不标PASS；保留原失败，**不因INVALID自动补一次采集或重开预算**。技术故障是否消费/可重试以原先授权的次数为准；已消费正式claim不得删除。
- 停止录制轨道，恢复viewport/pose/state/view及被改属性，回读并核源/媒体SHA。`getPixels`后存在但`enabled=false`的view不是有效裁切；捕获尺寸与实际viewport必须一致。

### 拍前成像证据合同

沿用`vr-production-plan/v2`，新增必填`scope.source_namespace`、`render_method`、`render_config`（渲染器版本、width/height/DPR、FOV轴/值及实际参数）及`render_validation={path,sha256}`。预检报告列为`assets.role=precheck_report`；每个证据列为`assets.role=precheck`，全部SHA进入原`BUNDLE_SHA256`，不能更新证据但沿用旧批准。

`vr-render-precheck/v1`报告最小结构：

```json
{
  "schema": "vr-render-precheck/v1",
  "source_namespace": "<current listing/work>",
  "capture_medium": "model_render",
  "validation_scope": "model_only",
  "render_method": "model_mesh",
  "render_config": {"renderer": "<version>", "width": 720, "height": 1280, "dpr": 1, "fov_axis": "vertical", "fov_deg": 85.57},
  "continuity_class": "cross_room_travel",
  "route": "<exact current route>",
  "coverage": ["<current spaces>"],
  "source_sha256": {"<source path as in assets>": "<sha256>"},
  "evidence_kind": "continuous_media",
  "complete_interval_reviewed": false,
  "checks": {"control": "PENDING", "visual": "PENDING", "playback": "PENDING", "state_restore": "PENDING"},
  "evidence": {
    "media": {"path": "<continuous media>", "sha256": "<sha256>"},
    "telemetry": {"path": "<actual camera/time controls>", "sha256": "<sha256>"},
    "review": {"path": "<actual full-interval visual review>", "sha256": "<sha256>"},
    "restore": {"path": "<state/source restoration check>", "sha256": "<sha256>"}
  }
}
```

占位状态不能通过。报告适用区间覆盖当前路线/关键连接，未查空间未验证，不把局部抄成全屋。control/playback/state_restore真实核验后填PASS；视觉按用户要求填`PASS`或`PASS_WITH_LIMITATIONS`，不是零伪影保证。无浏览器操作的restore说明未改状态并核原件；端点/其他方法不冒充`continuous_media`。

3.2.0带限制分支按[用户视觉合同](visual-acceptance.md)绑定`scope.visual_acceptance`的真实参考/决定/SHA及报告同对象，报告`visual_review.within_user_criteria=true`与实际限制逐项在正文可见；不增加第二次缺陷批准。旧更严FAIL保留，新标准下用已保存媒体另出比较报告；用户可定义接受范围，Agent不能说其批准永远无法改变视觉判定，也不能直接把未知/超范围结果填通过。

`review`可审未完成草案、不授执行；capture/同次post核当前身份/SHA/完整证据、三项技术控制PASS及有效视觉分支。缺项/漂移/PENDING/超范围FAIL拒绝。post_only仍只绑母版/批准、不要求新成像预检或采集。检查器核声明与绑定、不看片或认证作者/身份；最终实际接受由用户决定。旧v2/claim保持原字节，新字段/比较另版，不补造迁移。

## MOV-007：现实核证分支（缺项即 BLOCKED）

先回到当前项目的权威门禁与原始证据，不能只看旧交接或候选方法名称。至少核对：

- 当前房源与环境身份、房间/点位对应、门洞构件同一性；平台标签不等于实际身份。
- 源面朝向→世界坐标映射与配准、轨迹坐标/时间/逐帧位姿；“字段按米”不等于独立公制标定。
- 实体尺度与相机眼高 1.5–1.6m；抬升需证明几何和源画面可表达，不靠原点例外。
- 全程可达、门洞与家具遮挡、沿程至少 0.5m 净空；仅验起终点或静态箭头不够。
- 可用的真实采集或渲染路径、沿程视觉证据；专有模型文件存在不等于可用碰撞查询。

仅在现实核证分支缺证据时，列缺项及补证入口并保持该分支BLOCKED。模型内分支不因缺少现场资料阻塞；用户明确改变验收范围须登记，不能伪装为现实门禁已通过。脚本冻结、旧take接受或单点例外均不代替所属分支的取证。新房源从自己的素材预检开始。

## 有限探索与两个人工节点

1. **先规划候选，再有限核查**：先读用户接受基准，按对象/覆盖/顺序选当前方法与路线，再核关键连接；不用每镜通过才设计下一镜。参考的审美标准可复用，旧方法动态证据不可替当前源/路线。
2. **预算与停止线**：每个台账问题最多两组单变量局部对照，一次全路线预检；两组无改善、已定位源限制或预算耗尽即停止，提交限制/阻塞清单。不随机换角度、不换问题名续预算、不为小角度再跑全屋；局部改动只查该段及相邻连接。预算扩展需用户明确同意。
3. **拍前完整审核**：按 [图文脚本协议](illustrated-script.md) 实际交付整体PNG及真实源章节图卡、时间轴、来源/权利、首尾/字幕/BGM完整方案、风险和范围摘要；一次批准同时覆盖正式采集和列明后期。纯文字表或文件路径不算提交。
4. **一次采集、自主后期/QC**：入口核动态证据、按用户基准的有效视觉结果和实际整包批准并消费claim；已批准后期不再索权。技术/实际现象/标准比较/实播实听/用户最终接受分开，不为零伪影多拍。
5. **拍后验收**：确切最终文件/SHA、S-ID对照和限制交用户接受/退回。原件保留、不自动重拍；同母版且范围内的字幕/音乐/编码纠错是独立后期版本，不是再次拍摄。机器PASS不等于人工接受，用户审成片不自动解锁发布。

用户明确要求逐镜审核时才用该节奏；事实/权利缺项集中澄清、阻塞未决范围，不自动逐镜往返。若仍有其他项目强制旧流程，先报告冲突并按实际指令优先级处理，不默默绕过局部约束。

## 技术复用：规格不是通用拍法

已接受同点案例可作为 720×1280、30fps、H.264、静默母版、水平 FOV 55°、pitch/roll 0 的候选技术基准。固定原点离线六面重投影、五次平滑 `10u³−15u⁴+6u⁵`、起幅→启动→回转→停稳→落点可复用，但角度/时长仍由本镜对象及预检决定；长弧不得机械套用短镜节奏。

复用现有 `load_cubemap` / `base_rays` / `sample` / `rot` 前，绑定源码 SHA 并复现已接受基准的起尾/中段帧，明确误差度量、阈值与调度差异。编码通过不能证明构图/FOV正确。射线的 x/y 尺度分离：`kx=tan(h_fov/2)`、`ky=kx*H/W`；55°、720×1280 对应垂直 FOV 约 85.57°。案例 MAE 不是所有编码/源图通用阈值。源面覆盖须按实际 pitch/roll/FOV/插值实现复核，不把某案例避开 down 面推广为全程安全。

## 约 60 秒介绍片的整合次序

空间覆盖/顺序与连续性可行性→对象/章节预算→路径及静态/沿程预检→完整拍前包与脚本→许可范围内连续母版→声音/字幕/首尾浮层→最终 QC 与 SHA 人审。精确时长及容差写入合同；30fps、精确 60 秒为 1800 帧，不能拉伸旧短镜充数。

声音、完整口播/卖点字幕、标题事实、户型图内嵌文字、BGM 来源权利和 CTA 均在拍前整包审定；批准已覆盖的后期自主执行，未列事项才回审。母版静默是中间态，方案要求字幕/BGM却只交无音轨母版不得称完整成片。

## 证据适用范围

四房间 MOV-006 接受案例只证明该房源内特定 SHA 的同点回转；物理眼高/净空未独立核证，方法仍为观察候选，无通用复现证明。厨房、阳台及跨房间行进不由这些案例认证。TRN-004 硬切原型与未采纳提案保留为历史，不纳入新连续流程许可。各方法编号以项目方法库为准，禁止以专题目录名覆盖原方法定义。
