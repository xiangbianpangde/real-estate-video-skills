# 首尾镜头结构对齐协议

适用于用户提供当前/目标首尾截图，或要求房产片首尾与示例一致。与 [字幕规范](subtitle-style.md) 配合；本文件不授予素材、事实、CTA 或渲染许可。

## 1. 先定义对齐目标

- `reference_match`：室内背景开场 + 两行大标题 + 户型图浮层；室内背景尾镜 + 单行收束/CTA。不能降级为白底资料卡而宣称一致。
- `approved_variant`：用户明确批准的资料卡或其他结构。仍可交付，但列明与参考不同；不是参考结构通过。
- 优先级：本轮明确目标截图 > 本轮指定参考片同角色画面 > 历史模板。截图定空间结构，视频定动态/持续时间；二者冲突时先报告，不自行取舍。
- 先绑定当前候选的路径、SHA、尺寸、时长和阶段；同 take 号跨阶段不等价。取实际编码画面做比较，排除截图中播放器黑边、控件和水印；不得把播放器外围黑边加到输出。

## 2. 开场：三层合成，而非独立白底页

从下到上：本房源真实室内画面 → 户型图浮层（半透明浅色圆角底 + 保持原比例的图像）→ 两行大标题。户型图内部白纸可以保持不透明，半透明的是外部卡片底；不降低户型图本身透明度。户型图不裁墙线、标注，不拉伸、不补绘。

以下是参考截图视频区域的人工近似测量，供首次排版使用，**不是精确字体参数或跨项目硬阈值**。所有坐标用最终编码画布，`bbox=[left,top,right,bottom]`，归一化于 W/H；中心均为含描边包围盒中心，不是文本顶边。

| 层 | 起始几何 | 720×1280 换算建议 |
|---|---|---|
| 背景 | 覆盖整幅 9:16，露出室内空间 | 优先沿用已核验开场室内镜头；若需裁切，记录 crop，守住真实源边界 |
| 名称标题 | 中心约 (0.50W,0.285H)，含描边字高约 0.06–0.07H | 中心约 (360,365)，字高约 77–90px；黄字粗黑描边 |
| 面积/户型标题 | 中心约 (0.50W,0.37H)，字高约 0.065–0.075H | 中心约 (360,474)，字高约 83–96px；白字粗黑描边；整块宽约 0.84W |
| 户型卡片底 | bbox 约 [0.045,0.448,0.955,0.855] | 约 [32,573,688,1094]；浅色半透明圆角，初试 alpha 0.65–0.80，圆角约 0.03W，最终目视定值 |
| 卡片内户型图 | bbox 约 [0.075,0.470,0.925,0.830] | 约 [54,602,666,1062]；contain 保比例，实际 bbox 由素材宽高比确定 |

名称整行黄标是标题角色例外，不套正文“最多两处黄标”。标题大小必须按含描边实测，不能只放大字体参数却没核对输出。第二行应显著大于普通正文；不可保留旧资料页的顶部小字排版。

开场背景应与随后首个室内镜头自然衔接：合同写明是否共用同一源片及源时间区间、浮层退出方式、切点和源画面是否连续。不默认加花哨转场或伪造行走。参考抽样在 0/0.5/1.5 秒有标题卡、3 秒已转正文，这只给出范围，不证明退出切点；执行者须逐帧定位，不能硬套固定 2 秒或改变总片长。

## 3. 尾镜：室内画面收束，而非再次展示户型资料页

- 选择本房源已核验、方向/视角合理的卧室或已批准收尾室内镜头；不能直接搬参考视频片段，不能按名称猜房间 ID。
- `reference_match` 尾镜没有整幅白底资料页、深色户型图和顶部 CTA。CTA/收束作为单行字幕置于约 (0.50W,0.61H)，采用正文粗黑描边、白/少量黄标、无底框；含描边字高约 0.04–0.048H，按文字长度与左右安全边距调整。
- CTA 通常把行动词及本房源名称标黄，前半句白字；文案、名称和引导动作须各自获准，不能因参考存在就照抄。长文优先审阅分段，不缩成不可读小字。
- 参考末段抽样显示室内画面随时间改变，不能只验一张静帧便称动态一致；合同记录尾镜源区间、运动、CTA 起止、最后有效帧与音频尾音。
- 保留完整口播的约束不变。若当前尾段是免责声明，目标是一行留言 CTA，先给出冲突：保留免责声明按连续 cue 排版（文字层不同），或经批准改台本/重配音，或明确接受差异。不得直接删除、遮住或替换已批准口播，也不得擅自移走法务必需披露。

## 4. 一次提交的修订合同

执行者先交首尾布局/时间轴方案，不先出新视频：

1. 当前与参考路径/SHA；`match_target`；首尾镜头 ID；各自时间段。
2. 每层 `layout_role`、素材源/SHA/源时间、事实来源、文案、高亮词、bbox、锚点语义、字高/字体 SHA、底 alpha/圆角；实际户型主体 bbox。
3. 变更清单：背景替换、标题放大/重排、户型图卡片、尾镜背景/CTA/免责声明；每项授权状态。
4. `unchanged_scope`：正文画面/字幕、音轨、总时长、帧率等具体约束与基准 SHA。完整口播与目标存在冲突时单列待决，不自动改模式。
5. 已接受背景缺失时，先回源镜头门禁；仅“优化 skills”不解锁生成镜头。生产许可仍一次一 take、无覆盖、不得自动重试。

## 5. 实帧验收与负向回归

- 分别记录 `technical_passed`、`opening_structure_match`、`ending_structure_match`、`subtitle_coverage_passed`、`human_accepted`，不能互相替代。结构通过也不证明像素复刻；使用已批准容差及并排目视。
- 开场抽首个有效帧、卡片中点、退出前一帧/后一帧；尾镜抽进入前后、CTA 起止及最后有效帧。记录 PTS/帧号，核对无黑帧、跳回资料页、浮层残留、字形/墙线裁切或遮挡。
- 同角色参考/当前帧按视频内容区统一显示尺度，测含描边 bbox、层间距、卡片与文字比例；不能用全片平均 PSNR 证明首尾匹配。不同视角室内素材只能证明结构相似，不证明构图/运动一样。
- 未改正文与音轨按 [字幕规范](subtitle-style.md) 回归；新 take 浏览器播放至结束，媒体错误检查和确切 SHA 人审不省略。

| 输入场景 | 必须行为 |
|---|---|
| 已批准本房源室内源片、标题事实与 CTA，要求对齐 | 先提交三层首镜/室内单行尾镜合同，获一次性许可后执行；逐角色验证 |
| 只优化 skill，要求和示例一样 | 修规则/提方案，不渲染；“一样”拆成结构、动态、文字/音轨和技术参数 |
| 仅准改字号颜色，当前白底资料卡 | 列结构差异并请求补充范围，不能仅调字后报参考一致 |
| 要把参考名称、户型图或卧室片段直接复制 | 拒绝跨房源素材/事实继承，改用本房源核验源 |
| 尾段完整口播为免责声明，目标只留 CTA | 提出台本/覆盖冲突，未批准前保留口播，不删除、不增加渲染 |
| 旧资料卡主体守卫与新浮层位置冲突 | 为新结构重测主体 bbox；旧守卫仅保护未改资料卡，不套新布局 |
| 正文仍通过但首/尾一个不匹配 | 分项不通过，不声称整片与示例一致 |

## 证据等级

本协议源于当前/目标首尾截图及指定参考片和两个当前候选的编码抽帧观察；参数是人工近似起点。实际私有媒体与 SHA 留在媒体项目/会话，不复制到便携 skill。未完成整片播放/音轨实听，也未证明新生产 take 已达效果；由媒体执行会话核验新布局与授权后闭环。
