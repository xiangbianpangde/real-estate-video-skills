# 整体方案冻结细则

整体方案冻结解决"整片怎么拍"的问题，是逐镜与后期之前的上游门禁。整体确认不等于任何镜头执行许可。

## 版本化

- 每个版本独立目录或独立文件，不得覆盖历史方案、已登记图片、原始素材、合同、take 与审阅记录。
- 每次新版本写明相对上一版改了什么。
- 图片与正文同版本：Markdown 用相对路径嵌入 PNG，HTML/SVG 只作为图源。

## 整体设计要素

1. 空间覆盖与观看顺序。
2. 总目标时长与章节预算。章节预算不是逐帧时间轴。
3. 统一真实性规则。
4. 镜间衔接策略。
5. 方法候选池。

图中的箭头表示观看衔接，不表示行走路径或测绘结果。

## 方法分级

每个候选方法至少标注：

- 方法 ID；
- 类型（实拍采集 / 后期 / 叙事组织）；
- 证据状态；
- 原验证房源；
- 当前房源适用状态；
- 逐镜门禁要求。

第一房源已测配方、外部观察候选、静态素材与方法名称都不自动跨房源解锁。

## 冻结状态

| 状态 | 含义 |
|---|---|
| `DRAFT` | 仍在编写 |
| `IN_REVIEW` | 已交用户审阅，未批准 |
| `ACCEPTED_FROZEN` | 用户明确批准的指定版本与范围 |
| `SUPERSEDED` | 被新版本替代，原文件保留 |
| `BLOCKED` | 存在事实、权利、权限、素材或人审阻塞 |

只有用户明确接受/批准/冻结某个具体版本，且范围能绑定到版本 SHA，才可写 `ACCEPTED_FROZEN`。文件存在、机器检查通过、用户说"继续"、旧许可和已有试片都不算批准。

## 冻结不自动解锁的事项

点位与原生视角例外、1.5–1.6m 视高、0.5m 净空、全屋房间 ID 映射、具体 yaw/FOV/镜长、声音来源与权利、下一镜、整片生成、商业发布、CTA。

## 变更规则

覆盖、预算、方法类别、房源事实或成本发生变化，必须新建版本并回到审阅，不得静默修改已冻结文件。记录字段见 `freeze-record-template.json`。
