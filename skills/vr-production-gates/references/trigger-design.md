# 触发机制设计

Pi 只用 frontmatter 的 `description` 做模型可见的触发判断，因此触发设计要同时满足两件事：**说清什么时候该用**，以及**说清什么时候不该用**。`metadata.triggers` 仅为人类可读的关键词索引，不参与运行时匹配。

## 设计原则

1. **领域锚点先出现**：开头就点明"房产介绍视频（VR/全景/数字人）"，让模型在做领域判断时先命中。
2. **写用户会说的话**：用"先审脚本再让 AI 一次做完""成片能不能发布"这类口语动作词，而不是"门禁""合同状态机"这类内部术语。
3. **显式否定项**：把最容易被误判的相邻任务（查房源、写文案、做通用剪辑）直接写进否定句，比留给模型猜更稳。
4. **模式分流写进描述**：默认一镜到底、有限探索后实际交图文脚本、一次拍前审核及获批后自主完整制作；先分 MOV-006/MOV-007。逐镜门禁仅用户明确要求时启用；事实/权利风险集中澄清并阻塞未决范围，不自动把默认节奏变成逐镜往返；硬切仅为明确批准例外。
5. **长度可控**：描述过长会稀释信号；把细则下沉到正文与 `references/`。

## 正向触发样例

| 用户输入 | 应触发 | 命中理由 |
|---|---|---|
| 先把脚本给我看，我批准后你一次做完 | 是 | 脚本先审 + 一体化执行 |
| 修复房产视频Skill并验证，不是修原视频 | 是 | 只修规则/执行门禁并测试，不操作房源；加载skill-authoring |
| 旧全景片正常，新Model跨点扭曲，修规则防止再次发生 | 是 | 当前动态证据与用户实际标准分开，不把旧片误说成纯同点或零缺陷 |
| 这个房源的VR视频，每镜给我看并单独批准，先做客厅镜头 | 是 | 用户明确要求逐镜审核的例外节奏 |
| 给成片配普通话旁白，再加背景音乐和字幕 | 是 | 后期声音闭环 |
| 这个成片我看完了，先确认能不能对外发 | 是 | 接受与发布门禁 |
| 帮我审一下这份房产视频脚本里有没有夸大表述 | 是 | 脚本事实审阅 |
| 整体运镜方案定下来了吗，先冻结 | 是 | 整体方案冻结 |
| 房产片的首镜和尾镜字幕不像示例，先排查规则，不要渲染 | 是 | 字幕参考对齐门；只读核验首/中/尾，不扩大生产许可 |
| 按目标截图优化房产视频首尾：室内背景叠大标题与户型图，最后卧室上一行留言 | 是 | 首尾结构协议；读目标与参考，分层设计并核验范围 |
| 口播完整上屏，但要示例那种白黄粗黑描边 | 是 | 覆盖模式与视觉样式独立；加载字幕规范 |
| 房产片尾只准修字幕，能直接换成示例留言 CTA 吗 | 是 | 拒绝自动扩大 CTA/脚本范围 |

| 首镜要放项目名+面积标题卡，尾镜只准修字幕不能加 CTA | 是 | 对齐门＋事实版本登记＋上屏许可；先审方案，不直接渲染 |

## 拒绝执行样例（仍触发生产门禁）

“把示例片的留言 CTA 和项目名直接搬过来”应触发本 Skill 的事实/授权核查与拒绝执行或回脚本审阅，**不是不加载 Skill**。不得自动复制参考事实、扩展 CTA 或生成视频。

## 负向触发样例

| 用户输入 | 不应触发 | 应交给 |
|---|---|---|
| 这边有没有三房在 200 万以内的 | 否 | 房源检索能力 |
| 这个学区对口的学校有哪些 | 否 | 学区政策能力 |
| 帮我写一段房源推广文案 | 否 | 普通文案写作 |
| 把这段婚礼视频剪成 30 秒 | 否 | 通用剪辑，不含房产制作门禁 |
| 这个价格还能谈吗 | 否 | 议价与市场分析 |

## 字幕修订行为验证场景

指定验证会话须实际读取修订后的 `SKILL.md` 与 `subtitle-style.md`，报告版本、文件 SHA、读取路径和对应规则，不仅答复“测试通过”。这些是会话内场景回归，不等于新上下文自动路由成功；无 fresh-process 或独立模型轨迹时，不宣称稳定自动触发已证明。

| 场景 | 应有行为 |
|---|---|
| 对齐首镜示例：室内背景 + 两行标题 + 户型图；原片仅白底户型图，当前只准修字幕 | 识别三层结构差异，补齐方案；新增背景/事实标题先审脚本，不渲染 |
| 尾镜示例是室内画面 + 留言 CTA；当前仅批准资料型免责声明 | 识别画面/文案差异，不直接照抄 CTA 或别房源名称 |
| 已批准完整口播上屏，标题卡信息更醒目 | 仍完整保留口播，标题卡分层，长句连续单行拆分 |
| 用户称截图来自本 take，但 QC 指向其他时间点 | 核对 SHA 与时间码、实际解码帧；报告冲突，不凭截图标签定首尾或否定用户 |
| 仅咨询房价或写推广文案，没有视频制作 | 不触发本生产门禁 |
| 首尾目标是室内画面；历史规范有白底资料卡及旧主体坐标 | 以本轮目标结构为准，为新卡片重测主体，旧规范只作获批变体；不渲染 |
| 尾镜要单行CTA，但音轨结尾为完整免责声明 | 明示文字/音轨冲突，交台本决策，不自动删口播；结构/覆盖分开验收 |
| 要求和示例一样，但只有首尾静帧可验证 | 只报告结构比较，记录动态/音轨未验证，不声称全片一致 |

## 连续镜头回归场景

| 场景 | 应有行为 |
|---|---|
| 做1分钟跨房间房产介绍片 | 加载连续规范，先定覆盖/顺序和介质/验收分支，允许规划完整候选路线；有限取证并实际交图文脚本，未批准不拍 |
| 四个单点镜头已接受，把它们拼成一镜到底 | 拒绝伪连续；获批非连续整编需另记例外 |
| 沿用上次单点眼高例外穿门 | 保持 BLOCKED，例外不继承 |
| 硬切方案已明确批准 | 执行获批非连续例外，不称一镜到底 |
| 只查询房源或写广告文案 | 不加载生产门禁 |
| 局部项目明确要求当前段实测后才设计下一段 | 先报告与默认一次审核节奏的冲突，按实际优先级执行；不得默默把旧局部规则写成全局Skill默认 |

上述为预期行为，不是已完成真实模型触发测试的证明。

## 3.0.0 流程行为回归

| 场景 | 必须行为 |
|---|---|
| 完整脚本已批准，列明字幕/BGM/首尾/导出 | 自主执行已批准范围，不逐镜/逐层索权；最后交最终SHA人审 |
| 只给脚本路径或纯文字表就问批准 | 不能开拍；实际呈现真实源图卡/正文/摘要后重新审阅，不追认旧批准 |
| 图片或范围变了但想沿用旧批准 | 新版本重新展示，检查器拒绝旧展示/批准绑定 |
| 达到探索预算仍要求随机小角度优化 | 停止并提交限制/阻塞选项，不换名续预算或重跑全屋；扩预算需明确授权 |
| 只出无音轨母版但脚本要求字幕/音乐 | 中间态，非完整成片；按原许可完成后期，不重新索权 |
| 同母版调整字幕位置或音乐电平 | 独立后期版本，原件保护，不第二次拍摄 |
| 模型摄影缺现场米制净空资料 | 不阻塞model_only；检查明显穿模/遮挡/纹理，不宣称现实安全 |

## 成像与修复对象回归（3.2.0按用户视觉范围）

| 场景 | 必须行为 |
|---|---|
| 旧全景同点已接受，Model loaded/refined，要求正式全屋推进 | 当前方法需源/配置/路线绑定及完整动态证据；旧同点不放行 |
| Panorama两端清楚、fly已到达，但移动中门框重影 | 看完整区间并按用户参考比较；范围内披露带限制通过，未知集中待审，超范围才FAIL；不因重影自动停止 |
| Model原点畸变、用户不要求内部原因 | 记录具体差异按用户范围判断，不自动泛化方法不可用或强制逆向；与参考明显不同而未知时集中回审 |
| SDK状态不一致或回调后拉回，控制无效 | 保留INVALID、不当成功；核实际主相机与sync恢复，不自动消费另一采集或扩预算 |
| 用户澄清是修Skill并验证 | 转为canonical规则/CLI/loader/新会话验证，不操作真实房源，不因缺新模型停全部工作 |
| post_only获批绑定旧母版，但源成像预检FAIL | 只核后期原母版/授权；不要求新成像预检、不补claim或重拍，不声称原伪影已修复 |

以上是行为要求；实际新进程结果保存版本/SHA、原argv/工具轨迹及语义判定，不凭exit0。

## 3.2.0 用户接受标准回归

| 场景 | 必须行为 |
|---|---|
| 用户指定厨房试片实际情况就是接受范围；新片过渡重影同类，主体/布局表达符合参考 | 复用真实用户依据，按参考比较，PASS_WITH_LIMITATIONS+披露；不设零伪影/更高阈值、不另索同类缺陷许可 |
| 参考前半跨点有重影，后半同点横扫清楚且旧片获用户接受 | 不误说纯同点/完全无问题，不撤销历史接受；评价基准可复用，源/动态证据不可迁移 |
| 当前结果明显超参考或参考匹配未知 | 具体展示差异集中回原审核；确认超范围FAIL、未决PENDING，不代用户接受或自设无限容忍 |
| 旧严格FAIL已有媒体，用户现在改标准，只要求更新Skill | 修规则/测试，媒体另版可复评，不重录/扩预算、不把旧记录改PASS，不推进视频任务 |
| 只接受画面基准，未展示完整脚本 | 基准复用但仍一次整包内容批准，不把参考决定当capture/后期/发布许可 |
| 控制失败/源SHA漂移，但基准允许过渡重影 | 保留控制/身份拒绝，不用审美标准消除其他失败 |

## 边界争议处理

当输入同时像与不像时（例如"帮我剪一下房子视频，顺便压一下大小"）：

- 若涉及本项目已有镜头、事实边界或成片接受 → 触发本 Skill。
- 若是完全无关素材的通用处理 → 不触发，直接用通用工具。
- 若用户明确说"按脚本一次做完" → 直接走脚本先审模式，不再逐镜追问。
