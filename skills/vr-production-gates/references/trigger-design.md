# 触发机制设计

Pi 只用 frontmatter 的 `description` 做模型可见的触发判断，因此触发设计要同时满足两件事：**说清什么时候该用**，以及**说清什么时候不该用**。`metadata.triggers` 仅为人类可读的关键词索引，不参与运行时匹配。

## 设计原则

1. **领域锚点先出现**：开头就点明"房产介绍视频（VR/全景/数字人）"，让模型在做领域判断时先命中。
2. **写用户会说的话**：用"先审脚本再让 AI 一次做完""成片能不能发布"这类口语动作词，而不是"门禁""合同状态机"这类内部术语。
3. **显式否定项**：把最容易被误判的相邻任务（查房源、写文案、做通用剪辑）直接写进否定句，比留给模型猜更稳。
4. **模式分流写进描述**：默认脚本先审、备用逐镜门禁，让模型在触发瞬间就知道该走哪条流程。
5. **长度可控**：描述过长会稀释信号；把细则下沉到正文与 `references/`。

## 正向触发样例

| 用户输入 | 应触发 | 命中理由 |
|---|---|---|
| 先把脚本给我看，我批准后你一次做完 | 是 | 脚本先审 + 一体化执行 |
| 这个房源的 VR 视频按分镜生成，先出一个客厅镜头 | 是 | 单镜生成 + 逐镜门禁 |
| 给成片配普通话旁白，再加背景音乐和字幕 | 是 | 后期声音闭环 |
| 这个成片我看完了，先确认能不能对外发 | 是 | 接受与发布门禁 |
| 帮我审一下这份房产视频脚本里有没有夸大表述 | 是 | 脚本事实审阅 |
| 整体运镜方案定下来了吗，先冻结 | 是 | 整体方案冻结 |
| 房产片的首镜和尾镜字幕不像示例，先排查规则，不要渲染 | 是 | 字幕参考对齐门；只读核验首/中/尾，不扩大生产许可 |
| 按目标截图优化房产视频首尾：室内背景叠大标题与户型图，最后卧室上一行留言 | 是 | 首尾结构协议；读目标与参考，分层设计并核验范围 |
| 口播完整上屏，但要示例那种白黄粗黑描边 | 是 | 覆盖模式与视觉样式独立；加载字幕规范 |
| 房产片尾只准修字幕，能直接换成示例留言 CTA 吗 | 是 | 拒绝自动扩大 CTA/脚本范围 |

| 首镜要放项目名+面积标题卡，尾镜只准修字幕不能加 CTA | 是 | 对齐门＋事实版本登记＋上屏许可；先审方案，不直接渲染 |

## 拒绝执行样例（仍触发生产门禁）

“把示例片的留言 CTA 和项目名直接搬过来”应触发本 Skill 的事实/授权核查与拒绝执行或回脚本审阅，**不是不加载 Skill**。不得自动复制参考事实、扩展 CTA 或生成视频。

## 负向触发样例

| 用户输入 | 不应触发 | 应交给 |
|---|---|---|
| 这边有没有三房在 200 万以内的 | 否 | 房源检索能力 |
| 这个学区对口的学校有哪些 | 否 | 学区政策能力 |
| 帮我写一段房源推广文案 | 否 | 普通文案写作 |
| 把这段婚礼视频剪成 30 秒 | 否 | 通用剪辑，不含房产制作门禁 |
| 这个价格还能谈吗 | 否 | 议价与市场分析 |

## 字幕修订行为验证场景

指定验证会话须实际读取修订后的 `SKILL.md` 与 `subtitle-style.md`，报告版本、文件 SHA、读取路径和对应规则，不仅答复“测试通过”。这些是会话内场景回归，不等于新上下文自动路由成功；无 fresh-process 或独立模型轨迹时，不宣称稳定自动触发已证明。

| 场景 | 应有行为 |
|---|---|
| 对齐首镜示例：室内背景 + 两行标题 + 户型图；原片仅白底户型图，当前只准修字幕 | 识别三层结构差异，补齐方案；新增背景/事实标题先审脚本，不渲染 |
| 尾镜示例是室内画面 + 留言 CTA；当前仅批准资料型免责声明 | 识别画面/文案差异，不直接照抄 CTA 或别房源名称 |
| 已批准完整口播上屏，标题卡信息更醒目 | 仍完整保留口播，标题卡分层，长句连续单行拆分 |
| 用户称截图来自本 take，但 QC 指向其他时间点 | 核对 SHA 与时间码、实际解码帧；报告冲突，不凭截图标签定首尾或否定用户 |
| 仅咨询房价或写推广文案，没有视频制作 | 不触发本生产门禁 |
| 首尾目标是室内画面；历史规范有白底资料卡及旧主体坐标 | 以本轮目标结构为准，为新卡片重测主体，旧规范只作获批变体；不渲染 |
| 尾镜要单行CTA，但音轨结尾为完整免责声明 | 明示文字/音轨冲突，交台本决策，不自动删口播；结构/覆盖分开验收 |
| 要求和示例一样，但只有首尾静帧可验证 | 只报告结构比较，记录动态/音轨未验证，不声称全片一致 |

## 边界争议处理

当输入同时像与不像时（例如"帮我剪一下房子视频，顺便压一下大小"）：

- 若涉及本项目已有镜头、事实边界或成片接受 → 触发本 Skill。
- 若是完全无关素材的通用处理 → 不触发，直接用通用工具。
- 若用户明确说"按脚本一次做完" → 直接走脚本先审模式，不再逐镜追问。
