# 固定贝壳资料库适配

收到单套房源目录时先读取本页，使用 `scripts/inspect_listing_materials.py <listing-root>` 输出只读清单。目录名称是 `城市-房源编号-小区`，身份以目录编号和 `01-房源信息/房源信息.json` 对照；样例小区不是待制作房源，不跨套复用图片或点位。

| 固定目录 | 用途 |
| --- | --- |
| 01-房源信息 | 房源信息.json为摘要，原始详情/物料返回与链接清单核事实；字段缺失保留未知，不从装修图片猜事实 |
| 02-房源图片 | 室内照片作真实画面参考，小区照片不能代替室内；其他已确认照片仍核来源 |
| 03-户型图/原始户型图 | 正式户型候选；有户型图.jpg时优先查看，同时检查其他候选的实际内容 |
| 03-户型图/VR户型图 | catalog等辅助定位参考，不自动作为正式户型底图 |
| 04-完整VR素材 | VR入口、VR配置/defaultWork.json及vr-manifest.json、点位及空间清单、全景六面图、三维模型/贴图；核同套身份再使用 |
| 05-视频素材 | 既有分空间视频参考；文件存在不表示已完成连续采集 |
| 06-检查记录 | 核身份、完整性、缺失项；已有检查不能证明新路线动态通过 |

## 户型图选择

实际打开原始户型候选，选择清晰完整、房间/门窗可读的正式布局图。`floorplan-detail.jpg` 在一套资料里可以是彩色图，在另一套里可能是VR界面截图，所以文件名、所在文件夹或SHA均不能单独证明适用。若只有截图，披露缺失，先核资料中其他候选，不冒称已找到正式图。

记录选中原文件的相对路径、SHA和实际查看结果；保留备选及未选理由。户型浮层、完整方案板和正文使用同一选图。改换底图必须重新核点位坐标；旧截图坐标不能直接套到彩色图，近似示意须标明，不能称已精确校准。

## 从资料到剧本

先选本片卖点和连续路径，再选参考帧。点位是移动控制数据，不是“一点一章”的默认内容目录。短片减少覆盖空间，为转向、穿门和扫视留时间；按当前时长/禁拍要求设计，不设通用章节数量或最短秒数。

新剧本记录使用design_system.version=1.3.0；历史批准快照不重写。一镜到底的每次跨点在review_route.transitions记录from_pano、to_pano、movement=forward、view（转向及视线主体）、duration_s。原地转向/扫视在章节动作内写明。相邻点证明可连接，不证明画面连续、朝向正确或能在计划时间拍完。动态预检未做即标待验证；首尾浮层叠在连续室内源上，不额外插入静态图片切断原件。

交付只给一个中文审核入口：视频剧本.html，内含完整方案板、逐章图文正文及首尾效果。剧本正文.md、record.json、generation.json属于支持文件。不要另给路线板HTML，或用原始SDK字段和校准细节挤占主要内容；这些放支持记录。

## 点位标定与失败恢复

`点位清单.json`可能只有全景六面图URL；先检查实际字段，不按目录名假定已有房间归属。适配器的spatial_inventory列observers三维位置、楼层、相邻点和floorplan元数据入口，room_mapping_status保持UNVERIFIED。元数据入口存在不等于已有可用变换。

新草案用设计系统1.3，review_route.registration绑定实际用于绘图的PNG SHA，nodes记录room_id、room_evidence，registration.rooms记录正式图上的房间多边形。只需核本片使用点及必要连接，不为未使用的全屋点追求精确坐标。房间依据来自实际全景、SDK房间/点位对应或已有可复核证据；不能把本次拟合结果反过来作为归属依据。

按下列顺序自主解决，普通技术修正无需用户选择：

1. 优先核同套配置/SDK中已有的点位到户型对应。确认index、floor_index、模型轴（例如x,z）、图像方向/裁切/尺寸；检查是否遗漏镜像、旋转或把不同图层混用。
2. 有可识别几何对应时用world_similarity：准备覆盖不同方向的至少三处非共线锚点，另留未参与拟合的检查点，记录来源。`python3 scripts/storyboard/floorplan_registration.py anchors.json --fit`以最小二乘输出[a,b,tx,ty]，公式为u=a*x-b*y+tx、v=b*x+a*y+ty。镜像须先明确变换轴，不靠盲搜打分。容差max_error_px由图像分辨率和锚点可辨识精度说明，不设统一像素阈值；检查残差、独立点和房间归属，任一冲突均不能称标定成功。
3. 全局拟合失效但本片点位所属房间已核实时，采用room_schematic：在对应房间内部画近似点，完整保留户型、S-ID、方向/时码及逐章正文，明确位置和连线是房间级示意，不表示精确轨迹或穿门。不得把已知卫浴放到卧室、用不确定标签掩盖冲突，或只因拟合分数提高就接受结果。
4. 若连房间归属也未核实，继续查看相关全景/SDK标识和现有记录。资料确实缺失或相互矛盾且无法消解时，交代具体缺哪份对应、已尝试什么、影响哪些点；不把“要不要人工核对”交给用户，也不推荐删除户型路线图降低交付。只有需要用户提供无法取得的资料，或改变已确认内容范围时才提问。

可运行校验：`python3 scripts/storyboard/floorplan_registration.py route.json`。几何拟合、来源文件哈希及房间多边形检查各自只证明对应范围；不能认证人工填入的房间标签真实，也不能证明动态运动顺滑。实际成图还须目视点位、标签、方向和户型对应。批准旧版1.0–1.2快照保持原样，不追溯加字段。
