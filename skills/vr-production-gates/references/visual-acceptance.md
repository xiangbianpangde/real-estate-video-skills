# 用户定义画面接受范围

**用户决定接受标准，Agent记录现象、按该标准比较并交付。** 参考片不是“完美视频”，也不授权Agent把自己的理想画质加成用户要求。用户已明确“这条视频的情况就是我的接受范围”时，按该声明执行，不再问是否接受参考片里已存在的同类表现。

## 当前明确基准

2026-10-13用户以厨房布局横扫试片作为接受范围，事件`de658a6b`。指定视频SHA：`0c08ab62ee3a23437d79657428e2b89cc784ad20f44e695dd0bdd73228855bae`。真实媒体留私有，公开仅此SHA及脱敏说明，不复制房源事实/图像。

已核该片：约0.9–10秒官方Panorama跨点行进，4/5.5/7.25秒有门窗/墙线/吊顶半透明重影与边线弯折；到达后约10.6–17.6秒同点横扫，水槽、台面、吊柜和灶台布局可读，末尾停稳约3秒。用户接受的是该片实际整体效果，**不是零重影/零变形**。不要将它错误归为纯同点回转，或撤销此前接受。

这组时间只定位参考内容，不是新片的时长、角度或允许缺陷持续时长上限。另一房源需自己的源/路线证据；借用的是用户明确指定的评价基准，不是旧房源几何、批准或动态PASS。

## 评审步骤

1. 锁参考文件/SHA和用户原话/事件；先读参考真实画面及接受范围，而不是根据名字猜方法或质量。
2. 看当前完整相关区间，记录现象/位置/时码和覆盖、主体/布局可读性、运动与停稳。按用户基准比较**实际整体观看效果**；不能仅抽一张过渡重影帧就拒绝，也不以端点/回调/编码成功替代动态审看。
3. 同类表现且整体符合已声明范围：记录`PASS_WITH_LIMITATIONS`及原样缺陷披露，进入正常完整脚本审核。无需先修到无瑕疵、再调角度重试、换房/硬切或另索一次缺陷许可。
4. 确认超出用户范围才`FAIL`；依据不够用`PENDING`并把具体差异集中放入原拍前/拍后审核。用户可进一步扩大/收紧范围，保存新决定；不自行规定新的秒数、幅度、缺陷比例或“所有主体必须绝对稳定”门槛。
5. 观察事实不随标准改变：旧严格标准下的FAIL留原记录，按新用户标准用已保存媒体另出比较报告，不重录或改旧报告。标准修订不是预算重开、正式许可或最终用户接受。

不把“发生重影”直接等同“不适合介绍片”。也不把参考接受变成任意伪影无限可接受、把未知Model碎片与参考过渡自动等同、或替用户宣布新片已接受。差异具体陈述，比较证据不足则待审，不能把待审包装成已证实不可行。

## 状态与执行

- `checks.visual=PASS`：符合约定画面要求，**不表示逐像素完美**。
- `PASS_WITH_LIMITATIONS`：符合明确用户接受范围，保留实际现象/限制；是有效分支，不改写成“无缺陷PASS”。
- `PENDING`：未完成当前动态审看或是否在用户范围内尚未确定；可提交草案，不启动正式采集。
- `FAIL`：当前结果确定超出该用户范围；停止该候选，保留证据。

control/playback/state_restore仍分别核真实运行，用户审美基准不改SHA/源身份、伪造房况/覆盖、控制失败、损坏文件、次数及发布许可。这不是新增的用户审美范围；相关事实/授权仍按本任务明确约定。用户最终决定确切成片接受/退回，Agent的预检不是代签。

## 现有v2记录的最小扩展

有用户参考时在`scope`写以下对象，并把同一对象放入当前报告；参考/决定分别列`assets.role=acceptance_reference/acceptance_decision`，不是本房源`role=source`。模板默认给此占位；确实无参考时删除该对象及两项assets，不要求每位用户额外提供参考或批准视觉基准。

```json
{
  "visual_acceptance": {
    "reference": {"path": "accepted-reference.mp4", "sha256": "<actual SHA>"},
    "decision": {"path": "visual-decision.json", "sha256": "<actual SHA>"}
  }
}
```

决定文件`vr-visual-acceptance/v1`保存`reference_sha256`、`criteria`和原`user_event`（id、message.role=user、message.content）；`criteria`逐字取该事件文本，不用Agent改写。事件原话未单独写SHA时，由已明确指代的原会话/指定文件绑定该SHA，并在私有provenance保存定位；检查器不做身份认证，操作者要回查真实来源。已给的本轮决定可复用，不额外强制用户再回复“批准参考”。

当前报告另外写：

```json
{
  "checks": {"control": "PASS", "visual": "PASS_WITH_LIMITATIONS", "playback": "PASS", "state_restore": "PASS"},
  "visual_review": {
    "within_user_criteria": true,
    "limitations": ["<实际S-ID/区间与观察差异，不填抽象套话>"]
  }
}
```

报告仍需当前方法/源/配置/路线、完整连续媒体及遥测/目视/恢复证据；`within_user_criteria`必须来自实际比较，不因填写true认证画质。引用参考、SHA、决定原话/文件与限制必须在图文正文可见，进入原BUNDLE绑定和一次完整批准。`PASS_WITH_LIMITATIONS`没有有效用户依据或未披露限制时拒绝；有参考的`PASS`同样需比较报告，不能绕过参考。

未提供参考的旧合法PASS记录保留其原合同语义，不解释为全局零伪影要求；模板占位不能执行。`post_only`继续只核母版/实际后期批准，不要为纯后期新增成像预检。源证据、旧claim/报告及raw不迁移改写；新比较报告与新批准另存。

## 回归判断

- 当前结果与用户参考同类且在其范围内 → 披露限制、按参考评审，不因重影自动FAIL或强制换拍法。
- 只有参考、没有当前动态媒体/比较 → PENDING，不拿旧PASS替当前证据。
- Agent提出更高要求 → 标建议，用户未采纳不作阻断。
- 新结果明显不同但未知是否接受 → 展示具体差异集中待用户审核，不自设容忍阈值或自动接受。
- 模型/控制/技术FAIL → 按其明确范围处理，视觉基准不抹除其他错误。
