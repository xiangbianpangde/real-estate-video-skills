# 示例 · 一次完整的一体化生产

> 图文笔记。只画流程与判据，不含真实房源画面、素材或标识。

## 场景

- 已有一份真实 VR 素材集合与一份通过核证的户型资料图。
- 目标是 35 秒竖屏房产介绍视频，普通话匿名旁白，纯器乐底床，同步字幕。
- 事实清楚、无未核证房间归属 → 走**脚本先审**模式。

## 两种模式怎么选

![两种生产模式与门禁差异](01-two-modes.png)

选择依据只有三条：事实是否清楚、源面与位移是否有风险、用户是否愿意减少往返。
三者都为否时才用逐镜门禁；只要有一条说不清，就退回逐镜，不要赌。

## 脚本包长什么样

脚本包必须一次交齐，缺一项就不算可批准：

| 段落 | 内容 | 常见错误 |
|---|---|---|
| 镜头表 | 顺序、画面动作、时长、素材路径与 SHA | 只写"展示客厅"，不写看到什么 |
| 逐句台本 | 每句原文、时间码、事实来源 | 写"全屋南北通透"，无来源 |
| 字幕时间码 | 起止时间、末条不得越界 | 只写时长，不写时间码 |
| 声音 | 配音服务/声线、音乐方向、混音优先级 | 只写"配个音乐" |
| CTA | 默认空；非空时限定资料型表述 | 写"欢迎咨询"，涉及权利与商业 |
| 验收标准 | 编码、抽帧、浏览器、接受方式 | 只写"效果好" |

## 执行顺序

1. 预检：锁定脚本 SHA、素材 SHA、输出目录不存在。
2. 镜头：按脚本生成或编排，每镜留技术检查。
3. 整编：按脚本顺序与切点硬切，先出静默版。
4. 配音与音乐：候选资产各自记 SHA 与来源。
5. 字幕：按时间码烧录，先验证字形。
6. 混音、编码、全解码、抽帧、浏览器播放。
7. 交付：成片 + 脚本对照表 + 证据包 + 最终 SHA。

## 验收阶梯

![接受状态阶梯](02-acceptance-ladder.png)

交付报告里必须写清当前停在哪一级。"机器检查通过"不是"用户接受"，
"用户接受成片"不是"可以对外发布"。三者之间隔着独立的授权。

## 交付后怎么改

用户按脚本段落提意见，映射回段落 ID：

- 只改剪辑点、混音、字幕措辞 → 新版本，重新出 take。
- 改事实主张、镜头范围、素材、时长、权利 → 回脚本审阅，重新批准。

不要在成片上打补丁绕过脚本。脚本是唯一对齐基准。

## 失败处理

任一环节失败：停机、记录、不自动重试、不覆盖已有 take。
一次许可只允许一个输出尝试；输出目录已存在必须失败而不是覆盖。
