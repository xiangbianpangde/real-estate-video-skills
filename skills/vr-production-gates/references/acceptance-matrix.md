# 验收场景

| 场景 | 判断 |
|---|---|
| 第三次有明确假设的局部修复、第二次相关路线检查 | 已授权且有进展就继续，不因技能计数停止 |
| 重复相同试验无新信息或触及用户明确预算 | 说明源限制/取舍，必要时集中澄清 |
| 录制前初始化失败 | 保存准确错误、修复后重试；不冒充已经拍摄 |
| 同一完整内容获批，换输出目录或修参数 | 自主执行，保留原件；目录锁只防并发/覆盖 |
| 用户明确“不重拍”或限定次数 | 按真实用户限制，不用新文件名绕过 |
| 完整图文文档链接后自然批准，无Current URL/parentId/哈希阅读 | 内部绑定内容与真实回复后执行 |
| 用户答“先修改/先调整”，问题原文里含“批准” | 不把问题当答案，不进入后期 |
| 正文/来源或实质范围静默变动 | 内容快照失配；说明变化，不能沿用旧接受 |
| 用户不需要BGM、CTA或固定两行标题 | 不因模板强加；按实际范围输出 |
| 缺完整方案板、独立路线板、动作图示或所要求首镜户型 | 修完整交付，字段/图片数量通过不能替代 |
| 当前一镜到底，剪辑加速删中间源区间或硬拼 | 违背用户要求，修正；全源变速映射核连续 |
| 禁拍卫生间但回程或镜面显露 | 仍不符合本次要求 |
| 卧室一般取景，用户未指定屋内推进 | 优先考虑门口稳定扫视床铺与窗边；门口遮挡或细节需求不适用时另选机位，不据此强制所有房源站门口 |
| 静态端点清楚，动态未查 | 只报告静态，不能宣称丝滑 |
| 过渡重影在用户明确接受范围内 | 披露限制，不自动要求零伪影或再批同类现象 |
| 用户退回同类画面 | 以最新要求修正，旧带限制通过不当作接受 |
| 模型内轨迹通过 | 不宣称现实安全；不额外套通用眼高/净空阈值 |
| mcode批量code0但部分失败 | 保留成功，只补确认失败项；不静默换系统say |
| 音轨存在、浏览器播放结束 | 不等于实听合格；按实际条件说明 |
| 完整字幕要求却交关键词、缺字或时码错位 | 修字幕与音轨同步，版式模板不豁免漏字 |
| 只修改Skill | 运行相关规则/工具检查，不自动制作视频 |

这些场景是验收合同，相关自动/真实验证结果以项目记录为准，不将合成fixture当成房源画质证明。
