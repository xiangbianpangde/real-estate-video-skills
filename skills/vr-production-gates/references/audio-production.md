# 声音制作与验收协议

## 入口与授权

开始后期先读取当前用户指令、获批声音方案及项目已有成功链路。用户指定 mcode 时，先读取本机 mcode-tools-master Skill，发现并查看当前配音/音乐工具 schema；记录实际入口、模型、音色、参数和回执。历史成功不等于当前可用。mcode 是主机，媒体调用使用其 mcode-tools Connector；独立 CLI 可能缺少主机认证上下文。

不得因工具未直接注入、PATH 缺入口、一次关键词未命中，就默认换成系统 say、其他生成器或任意素材库。当前入口失败应保留准确错误；需要换来源或新增未授权费用时说明具体差异。用户明确要求修复声音及使用指定链路时，不重复索取已有后期授权。

## 工具异常与部分成功

- **主机入口**：独立mcode-tools缺`shared-broker`上下文时，回到已登录mcode主机调用媒体工具。先发现准确`tool_name`再查schema，不猜简称，不复制或输出凭据，也不手工伪造认证环境。
- **回执逐项核对**：`code=0`、进程退出0不证明批量全成功；检查`total_requested/total_success/total_failed`、全部成功资产和失败索引。每个请求显式设唯一`output_file`，将成功文件与原请求绑定；计数不一致、漏项、重复项、身份不明则停止补发。单条返回不能套批量schema。
- **429补失败项**：只保留失败索引对应的原参数，成功资产绝不再生成；遵守服务Retry-After，没有时默认30/60/120秒退避，每失败项最多三次额外尝试，每次保存独立回执。失败持续到上限则保留已完成资产并报告阻塞，不换提示词、不无限重试。401/403、权限拒绝、未知错误或混合非429失败不自动重试。
- **可执行检查**：批量结果用[回执检查器](../scripts/check_media_batch.py)检查；退出0表示分项可信，仍须看`complete`。`complete=false`只允许429补发清单，不是媒体制作完成。检查器仅离线核回执，不调用服务、不等待、不认证素材实际内容；文件名不匹配也拒绝，不能猜对应关系。

```bash
python3 scripts/check_media_batch.py --request tts-request.json --response tts-response.json --retry-output retry-request.json
```

命令从Skill目录运行；输入为私有制作目录的真实JSON，输出是新文件。已有文件拒绝覆盖。回执检查成功且`complete=false`时，按退避规则调用补发清单；再次检查补发回执并合并原请求映射，全部项已下载核文件/SHA才算资产齐备。

- **运行中断**：mcode超时或达到步骤上限，先读已经落盘的回执和下载映射；存在完整成功证据则继续下载/核验，只有失败项可按规则补发。缺生成结果时先查询任务状态或报告未知，不能把未知当失败直接重做。
- **模型透明**：接口未暴露模型名就写“未暴露”；不能把历史`speech-2.8-hd`等模型名当作当前事实。临时签名URL与凭据不进公开仓库，媒体原件和回执留在私有制作目录。

## 转录、对齐与分析边界

模型回答中的`[00:00–00:02]`不是接口提供的音频时间戳。只有真实时码字段或基于实际音频运行的对齐工具可作为同步依据；ASR文本核内容与已知台本强制对齐是两件事，后者不能证明音频没有漏字。

出现低置信、重复/幻觉、漏句或原文不符时，不拿期望台本覆盖错误作为“验证通过”。保留第一次结果，去掉台本提示独立重识别；核已识别文本、实际波形与对齐质量，必要时局部重新对齐。专名/同音字不能直接判配音读错，也不能直接判完全正确；记录差异并安排人工核听。机器核验与人工听感分别标状态。

需要音频理解时先核具体媒体、目的地与既有授权。自动审批明确拒绝远端分析上传后，不改工具或间接调用绕过；保存拒绝原因并优先本机分析。本机也无法完成的核验明确标未验证，只有确实需要额外授权时才提供具体上传对象、目的和范围供用户决定。生成授权不自动等于任意其他用途上传授权。

## 先语义，后字幕

1. 将获批完整口播按章节整理成连续、可朗读的句子，保留事实、CTA及免责声明。字幕换行不是配音生成边界。
2. 按完整章节或整段生成，选择自然音色与语速；禁止为每个短字幕 cue 单独生成后拼接。确需修补发音时保留上下文并检查接缝。
3. 使用返回的音频时间戳或实际对齐工具取得句/字时码；先安排旁白到实际画面，再生成完整口播字幕。不得把平均字符时长冒充逐字对齐。
4. 记录各章画面窗口、实际语音起止、句间与章间最大空白、总语音覆盖率。画面窗口只限定叙事落位，字幕同步必须来自最终音轨。
5. 明显空白逐项解释用途并检查听感；例如短配音分散到长片形成20秒无解说，不得只凭“未越界”通过。没有适用于所有片子的覆盖率阈值；本片目标与可接受留白要写清。
6. 语音过短先调整自然语速、章内落位与呼吸；仍无法满足节奏时明确缺口。不得擅自补卖点、机械拉伸、切断末句或悄悄改动获批画面时长。改台本按既有回审范围处理。

## 音乐与混音

音乐方向先于生成/选材：本片情绪、节奏、旁白空间、器乐/人声、允许起伏和使用权。按实际工具 schema 生成；候选与最终入轨分开。不能仅因历史 mcode 成功就复用不适合的新片音乐。

保存源资产、SHA、来源/权利、真实时长、响度/真峰值和生成回执。短音乐延展要记录方式、次数、接缝时码，并检查实际接缝；不以文件拼接成功证明无缝。旁白优先，按完整语句处理音乐让位及平滑恢复，检查频繁抽吸、突变、语音遮盖和尾部结束；不得只靠固定电平参数宣称听感合格。

## 验收与证据

- 正例：完整章节TTS→实际语音时码→最终时间轴→字幕；逐项核留白；音乐方向、接缝、让位与整片节奏完成试听，保存听者/方式/文件SHA/问题记录。
- 反例：29个短字幕分别TTS；41.8秒语音散落106.5秒且20.1秒空白未评估；任意音乐配固定ducking；浏览器未静音播放结束后标“实听通过”。
- 技术检查含解码、音轨完整、响度、削波、时长、字幕同步和遗漏；它们不等于音色、韵律或音乐适配合格。
- 明确分开 `technical_passed`、`audio_listening_verified` 和 `human_accepted`。无真实听取条件时标未实听，说明缺口；可交用户试听候选，不能声称声音已验收。保留旧成片及原件，声音纠错输出独立后期版本，不重新采集。
