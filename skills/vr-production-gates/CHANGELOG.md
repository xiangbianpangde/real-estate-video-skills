# Changelog

## 3.1.0 - 2026-10-13

- 锁定修复对象：修/验证本Skill只改canonical与配套、运行规则/CLI/新会话验证，不自动操作房源、导航或录制，也不以视频源不足阻塞Skill修复。
- 明确同点全景、Model、SDK全景跨点和真实实拍方法；旧同点/端点/loaded/回调通过不能迁移成当前方法动态PASS。已知视觉FAIL按原预算停止，不以精确内部归因作为前置，不随机换角度/near/材质重跑。
- 复用现有拍前检查器：v2范围新增源身份/方法/配置/预检报告SHA，报告和四类连续媒体/遥测/目视/恢复证据进入原BUNDLE绑定；正式capture及同次post拒绝缺报告、静态冒充动态、控制/视觉FAIL和方法/源/路线/配置漂移。草案review与绑定原母版post_only保留，不补造旧批准或claim。
- 增补SDK实际主相机/状态同步守卫、临时属性描述符恢复、轨道停止和原件SHA回核；INVALID不自动重试，不改为第二次生产take。实际媒体PTS与墙钟、CFR及视觉分别核验。
- 检查器仍是结构/SHA入口门禁，不自动识别畸变、不认证报告作者/真假、不拦截直接绕过；规则修复不等于现有视频已修复。无新渲染器、依赖、Skill副本或真实房源采集。

## 3.0.0 - 2026-10-12

- 统一默认：有限自主探索→实际呈现真实源图文脚本→一次完整制作批准→一次正式采集及获批后期→按S-ID审成片；逐镜仅用户明确要求，不再风险自动分流/逐层索权。
- 探索默认一次关键预检、每台账问题最多两组定向对照、一次全路线预检；无改善/已定位源限制/预算耗尽停止，局部变更仅查受影响段，不随机全屋重跑。
- 新增图文脚本协议/模板与最小Python拍前检查：真实PNG嵌入、卡片内容、SHA、实际提交/用户回复事件、范围摘要、单采集claim；失败关闭、并发只一个占用。无新依赖，非全局权限沙箱。
- 一次完整批准同时含采集与列明首尾/配音/字幕/BGM/编码/QC，不等中间母版人审；后期独立版本与正式拍摄次数分开。另有新审核的post_only版可绑定原母版、拒绝capture，不要求重建旧claim；原件不可覆盖、不自动重拍。
- 同步model_only与physical_verified分支、当前要求优先于截图旧拍法、静默母版不算完整成片；真实性、禁用公摊、视觉/实播/音轨/最终人审与发布边界保留。
- 图文示例与默认流程图更新；P001/P004添加日期兼容说明并保留历史正文，防止旧“逐镜备用/一次输出”误覆盖当前完整制作与post_only分支。历史批准不迁移追认，规则修订不修改现有媒体/模型或补造旧审核。私有项目局部执行规则同步另记其append-only日志。

## 2.8.0 - 2026-10-11

- 新增 `capture_medium` / `validation_scope` 分流：当前任务可使用真实房源3D模型与贴图进行 `model_only` 连续摄影，不再以前现场测量阻塞模型内测试。
- 明确模型内连续相机、穿模/遮挡/纹理检查与现实安全核证分离；模型内通过不得宣称现实现场行走或物理安全通过。
- 要求绑定当前房源模型/贴图 SHA，禁止跨点跳转、AI补画面和跨房源继承；保留脚本审核、单take许可、QC、实播与人工接受。

## 2.7.1 - 2026-10-11
